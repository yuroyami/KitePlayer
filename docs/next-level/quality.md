# Program Q: quality, CI, documentation

Read `README.md` in this directory first. Facts verified against the tree: seven CI jobs
(`.github/workflows/ci.yml`), no emulator, no `xcodebuild`, no size measurement. Dokka is
configured for ten modules (`build.gradle.kts:167-176`) and no workflow publishes it; KiteFFmpeg's
`docs.yml` publishes mkdocs and Dokka to Pages. No benchmark tooling; two hand-rolled harnesses
(`ShaderBenchmark.kt`, `ConversionCostTest.kt`). No `dependabot.yml` here (KiteFFmpeg has one).
No changelog, no release-notes script. The subtitle parsers have 29 tests and no fuzzing. The
samples have no file picker on either platform. Several public sentences contradict the tree,
listed under Q10.

### Q1 Android device tests in CI, on an emulator. Size M, Tier 2. [owner] allows the action

**Why.** Every Android row in the ledger rides DEVICE-DAY. Most of them are software: format
matrix, MediaCodec configuration, the view. An emulator runs those on every push.

**Depends on:** nothing.

**Files.** Modify `.github/workflows/ci.yml` (new job `android-emulator`), and whichever
`androidDeviceTest` source sets need media staged (find how `FormatMatrixDeviceTest` reaches its
clips: `grep -rn testmedia kiteplayer-ffmpeg/src/androidDeviceTest`).

**Contract.** Job on `ubuntu-24.04`: enable KVM (`echo 'KERNEL=="kvm", GROUP="kvm", MODE="0666", OPTIONS+="static_node=kvm"' | sudo tee /etc/udev/rules.d/99-kvm4all.rules`,
`sudo udevadm control --reload-rules && sudo udevadm trigger --name-match=kvm`), then
`reactivecircus/android-emulator-runner@v2` with `api-level: 34`, `arch: x86_64`,
`target: google_apis`, `profile: pixel_6`, running the device test task of `kiteplayer-output`,
`kiteplayer-ffmpeg`, `kiteplayer-view` and `kiteplayer-compose-video` (find the task name with
`./gradlew tasks --all | grep -i connected`; the KMP library plugin names it differently from
`connectedAndroidTest`). Generate `testmedia` first with the runner's ffmpeg (`sudo apt-get install ffmpeg`,
then `./scripts/testmedia.sh`; the pin check decides whether the distro's version is accepted).
Rows that need hardware decoders (HEVC Main10, AV1) are expected to report their refusal path on
the emulator; the job's comment says so, and the matrix runner's `MustPlay` for those rows is
downgraded to `MustSurvive` under a `KITEPLAYER_EMULATOR=1` environment variable read by
`FormatMatrix.kt`.

**Tests.** The job itself. Locally, `KITEPLAYER_EMULATOR=1` on the host matrix run changes the
two rows' verdicts and nothing else.

**Commit.** `ci: Android device tests run on an emulator on every push`

### Q4 Artifact size ratchet. Size M, Tier 2

**Why.** The size tiers appendix in `MASTER_PLAN.md` says no size is promised before it is
measured. Nothing measures. A dependency that doubles the AAR would land unnoticed.

**Depends on:** nothing.

**Files.** Create `scripts/artifact-sizes.sh`, `size-baseline.txt`. Modify `.github/workflows/ci.yml`
(`macos-host` job, after the tests).

**Contract.** The script builds `jvmJar`, `bundleAndroidMainAar`, `macosArm64MainKlibrary` and
`iosArm64MainKlibrary` for every publishing module (read the list from `settings.gradle.kts`'s
includes minus samples and unpublished modules), prints a table `module target bytes`, and
compares each line to `size-baseline.txt`: more than 10 percent above fails and names the line;
`--update` rewrites the baseline. CI prints the table into `$GITHUB_STEP_SUMMARY`. The baseline
moves by procedure like the other ratchets (`GOTCHAS.md` section 3): same commit, old and new
numbers in the message.

**Tests.** Running with a baseline edited down by 20 percent fails naming the module; `--update`
then a plain run passes.

**Commit.** `ci: artifact sizes are measured and ratcheted`

### Q5 A perf gate without a dependency. Size S, Tier 1. [owner] may prefer `kotlinx-benchmark`

**Why.** The resampler, the tempo stage and the CPU colour conversion are the hot paths and
nothing watches them. A benchmark library is a dependency decision; a test with a generous bound
is not.

**Depends on:** nothing.

**Files.** Create `kiteplayer-core/src/jvmTest/.../PerfGateTest.kt`, `kiteplayer-ffmpeg/src/jvmTest/.../ConversionPerfGateTest.kt`
(beside `ConversionCostTest.kt`). Modify `.github/workflows/ci.yml` (grep `PERF ` lines into the
summary).

**Contract.** Each measurement: three warm-up runs, seven timed, the median reported as
`PERF <name> ms=<n>` on stdout, and asserted below a bound chosen at ten times the number
measured on this Mac, so a regression of an order of magnitude fails and noise never does:
`resample.48k.to.44k1.10s`, `tempo.wsola.1x5.10s`, `convert.yuv420p.1080p`. The bounds are
constants in the test with the measured number beside each in a comment.

**Tests.** The gate itself, plus a self-check that a deliberately slow lambda trips the bound
(kept as a test of the harness, tiny).

**Commit.** `test: a perf gate on the three hot paths, no new dependency`

### Q6 Subtitle parser fuzzing. LANDED 2026-09-03

Nothing was found: five harnesses, 2,000 mutations per seed over every fixture, all green on the
first run. Falsified by breaking SubRip's timing line and ASS's start/end order on purpose; the
harness caught both and the other three stayed green.

### Q6, as planned. Size S, Tier 1

**Why.** Three parsers, 29 tests, all on well-formed input. Subtitle files from the internet are
not well formed.

**Depends on:** nothing.

**Files.** Create `kiteplayer-subtitles/src/commonTest/.../ParserRobustnessTest.kt`.

**Contract.** For each parser (SubRip, WebVTT, ASS): take every inline fixture from the existing
tests as a seed; with `Random(1)`, produce 2,000 mutations per seed from these operations: flip a
byte, truncate at a random offset, duplicate a random line, swap CRLF and LF, insert a BOM,
insert a random code point in the 0x80 to 0x10FFFF range, delete a random line. Invariants:
parsing never throws anything but the parser's own documented exception (find which; if none is
documented, the invariant is "never throws" and a failure is a bug to fix in the same commit),
every returned cue has `endMicros >= startMicros`, and one parse takes under one second of wall
time (a spin is a hang, and `runTest` virtual time would hide it).

**Tests.** The test. Every failure it finds is fixed under the same commit with the mutation
that found it pinned as a named regression test.

**Commit.** `subtitles: the parsers survive two thousand mutations of every fixture`

### Q10 The doc-truth sweep. TREE HALF LANDED 2026-09-03; the release page is the owner's

A second tree pass ran on 2026-09-03 after the audio and session work landed. The README's
feature table had drifted behind ten shipped calls at once, which is what a table of calls does
when nothing points at it. Two corrections worth remembering:

- **The table claimed a capability the default does not have.** The first draft of the volume row
  said the player boosts to 2x. It does not: `volumeCeiling` is 1 by default and an application
  has to raise it. A feature table that reads like a promise has to be checked against the
  DEFAULT, not against what the code can be configured to do.
- **Read the API dump, not the source.** Every name in the table was checked against
  `kiteplayer-core.klib.api`, which is where a name that no longer exists shows up as absent
  rather than as a grep hit in a comment.


Every claim below was verified against the tree before it was touched, and all six KitePlayer ones
were real. Two things worth carrying forward:

- The KiteFFmpeg half turned out to need NOTHING, and the reason is written into it below. An item
  that says "fix this prose" can be answered with "this prose is correct", and that answer has to
  be recorded or the next executor re-opens it.
- `SubtitleConfig.lookahead` was deleted rather than implemented. It removes a public field, which
  is a real ABI change on a 0.0.x line: the alternative was keeping a knob whose own KDoc admitted
  nothing read it, which is worse than the break.
